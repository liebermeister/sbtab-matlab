# Changelog

Version numbers have the form MAJOR.MINOR.PATCH. MAJOR changes when existing calls may stop working.

## Not released yet

- Reaction orientations (user decision 2026-11-19): a plain database ID in `!ReactionIdentifiers:<DataCollection>` / `!Reaction:Identifiers:<DataCollection>` now means `orientation-equal` (before: orientation unknown, R78 warning); a reversed orientation must be written as a JSON string `["R01068","orientation-reversed"]`, `["R00771","orientation-equal"]` is still allowed. In `!ReactionMiriamAnnotation` / `!Reaction:MiriamAnnotation`, the orientation element may be omitted for `orientation-equal`. `sbtab_reaction_identifiers_parse` returns `orientation-equal` (sign +1) for plain IDs; `sbtab_reaction_identifiers_format` and `sbtab_miriam_annotation_format` write orientation-equal in the short form by default (new argument `explicit`); `sbtab_document_validate` no longer warns about plain IDs. Example files: `["ID","orientation-equal"]` entries replaced by the plain IDs.
- `sbtab_load_quantity_data`: an ID column `...:Identifiers:bigg.metabolite` is also found under the old name `bigg.compound`.
- `sbtab_document_validate`, new rules for SBtab 1.1 and 1.2 (2026-11-19): R79 (a file with several tables begins with a document row `!!!SBtab`; warning) and R10 changed (a missing SBtabVersion, neither in the document row nor in the table declaration row, gives a warning; before, it was valid). SBtab 1.0 files are not affected
- `sbtab_document_load_from_one`: tables without SBtabVersion get the SBtabVersion of the document row (as the specification says; R16). Before, they had no version, so that `sbtab_document_save` treated them as tables of another version (e.g. the columns of Definition tables were renamed)
- Examples: files with several tables begin with a document row (`!!!SBtab Document='...' SBtabVersion='...'`; the version was removed from the table rows): `BIOMD0000000061`, `SBtab_specification_example_tables`, `escherichia-coli_noor_2016_model` (Document shortname `escherichia-coli_noor_2016_model`, the former Document text is the DocumentName), `escherichia-coli_wortel_2018_model`, `escherichia-coli_ccm_aerobic_ModelData`, `hynne/BIOMD0000000061_modeldata`, `jiang_modeldata`, `pfk_modeldata`, `teusink_modeldata`, `sigurdsson_model` (1.2). Example `jiang`: names and KEGG IDs of the compounds Cytc2p (ferrocytochrome c, C00126) and Cytc3p (ferricytochrome c, C00125) corrected (they were swapped), and the compounds of the corresponding data rows; KEGG reaction IDs of v24 (R02163) and v28 (R00086) corrected
- Reaction annotations with reaction orientation (SBtab 1.1 and 1.2). Reaction tables: new columns `!ReactionIdentifiers:<DataCollection>` (entries are JSON strings `["R01068","orientation-reversed"]`: database ID and reaction orientation, `orientation-equal` or `orientation-reversed`) and `!ReactionMiriamAnnotation` (like `!MiriamAnnotation`, with the orientation as a third element). Quantity and QuantityMatrix tables: the existing column `!Reaction:Identifiers:<DataCollection>` now has entries of the same form (plain IDs, as in older files, are read as IDs with unknown orientation), and the new column `!Reaction:MiriamAnnotation` is like `!ReactionMiriamAnnotation` (definitions tables 1.1 and 1.2). `!MiriamAnnotation` entries are JSON lists `[["qualifier","URN"], ...]` in SBtab 1.1 and 1.2. New functions `sbtab_reaction_identifiers_parse` (also returns the orientations as +1, -1, NaN), `sbtab_reaction_identifiers_format`, `sbtab_miriam_annotation_parse` and `sbtab_miriam_annotation_format`. `sbtab_load_quantity_data` matches the IDs in reaction identifier columns (orientation ignored). `sbtab_document_validate`: new rule R78 (warnings for malformed entries, entries without orientation, and `!ReactionIdentifiers:X` together with `!Identifiers:X`); a Reaction table with these columns counts as identified (R51). New example `sbtab-1.1/reaction_annotations`, test `tests/test_reaction_annotations.m`. Examples `SBtab_specification_example_tables` (table names without the example numbers of the specification) and `kegg_reactions_CC_ph70`: `!Reaction:Identifiers:kegg.reaction` entries with orientation (`orientation-equal`). Model data examples (ecoli / escherichia-coli, ecoli_ccm_aerobic, hynne, jiang, pfk, teusink): `!Reaction:Identifiers:kegg.reaction` entries with the orientation of the model reaction relative to the KEGG reaction (from the KEGG equations, compared by KEGG compound IDs); `hynne_reaction`: column renamed to `!ReactionIdentifiers:kegg.reaction`; entries that are no KEGG IDs of the reaction (`RPTSsy`, some Jiang rows) are left as plain IDs. Entries `nan` count as empty. The rule is not applied to SBtab 1.0 documents
- `sbtab_load_text_table` / `sbtab_table_load`: in tab-separated files, fields that start with a double quote are now unquoted (`""` stands for a double quote inside the field), as in comma-separated files and as written by spreadsheet programs; double quotes inside other fields (e.g. JSON strings) are kept. Before, quotes in tab-separated files were always kept. `sbtab_table_save` encloses fields that start with a double quote or contain a tab or a line break in double quotes, so they are read back unchanged. The Python package sbtabpy reads files in the same way
- New functions `sbtab_table_n_rows` (number of rows of a table object) and `sbtab_table_set_column` (replace the entries of a column, SBtab column or column without `!`, or add the column); from the IMF toolbox (`imf_sbtab_n_rows`, `imf_sbtab_set_column`), used by the data-orientation functions of the Metabolic Network Toolbox
- `sbtab_document_validate` checks SBtab 1.2 documents with the rules of SBtab 1.2 and the 1.2 definitions table (before, with the rules of 1.1 and, because of the renamed definitions files, also the 1.1 definitions table, so the columns of 1.2 table types were not checked). The SBtab 1.2 rules (preliminary, listed in `conformance/1.2/rules.md` of the SBtab project) are those of 1.1 plus: R62 (decimal commas) is an error; R74 (Regulation tables need `!Regulator` and `!Target`; `!RegulationType` is activation, inhibition, dual or unknown); R75 (`RowTable`/`ColumnTable` of sparse matrices name table types of the document, whose keys are used in `!RowID`/`!ColumnID`); R76 (attributes in the first cell of the declaration row) and R77 (attribute values in simple quotation marks). New rule R73 (SBtab 1.1 and 1.2): elements of kinetic regulation formulae (`!KineticRegulation`, `!ActivityCondition`) have a sign (`+`, `-`, `+-`, `?`); undefined elements are reported as Info. Versions above 1.2 are checked with the 1.2 rules
- New SBtab 1.2 examples `feed_forward_loop` and `yeast_transcription_network_chang_2008` (`Regulation` tables; the yeast network also with `Regulator` and `Gene` tables and `!RegulationType` `unknown`), converted from the SBtab 1.1 examples, which keep their `Relation` tables
- Regulation networks and definitions tables (SBtab 1.1 and 1.2): new column `!ActivityCondition` of Gene tables (regulators of the gene's expression, e.g. `+ TF1 - TF2 ? TF3`); In kinetic regulation formulae (`!KineticRegulation`, `!ActivityCondition`), the sign `?` denotes regulation of unknown type (e.g. `+ ADP ? ATP`); entries without sign (older files) are still read as unknown; SBtab 1.2 Regulation tables: `!RegulationType` value `unknown` (SBO:0000596 modifier of unknown activity); new table attributes `RowTable`, `ColumnTable` and `QuantityType` (sparse matrices). `sbtab_regulation_network_save` writes `unknown` and `?` for arrows without sign, and weights of the arrows (field `weights`, e.g. NCA weights) to a SparseMatrix table (TableID `RegulationWeight`, attributes `RowTable='Gene'`, `ColumnTable='Regulator'`, `QuantityType`, default `regulation weight (log scale)`, option `weight_quantity_type`); `sbtab_regulation_network_load` reads them (fields `weights`, `weight_quantity_type`). New example `sbtab-1.2/nca_network` (transcription network with NCA weights, as in the SBtab 1.2 specification). SBtab 1.1 examples: `!KineticRegulation` entries without sign written as `? X`
- New functions `sbtab_regulation_network_load` and `sbtab_regulation_network_save` (folder `sbtab-formats/regulation-network`): regulation networks such as transcription networks (regulators, targets, arrows and signs) in SBtab documents, with `Gene`, `Regulator` (`!Type` `transcriptional regulator`) and `Regulation` tables, or with a column `!ActivityCondition` in the `Gene` table; used by the NCA toolboxes. Test `tests/test_regulation_network.m`
- Definitions table of SBtab 1.1, Regulator tables: the columns `!TargetGene`, `!TargetOperon`, `!TargetPromoter` are replaced by `!Target` and `!TargetType` (e.g. `gene`, `promoter`). Example `lac_operon` (SBtab 1.1) changed accordingly; example `SBtab_specification_example_tables`: new Relation example (protein interactions, as in the specification); new example `protein_interactions` (SBtab 1.1, Relation table)
- Definitions table of SBtab 1.2, Regulation tables: column `!Regulator` now comes before `!Target`; new columns `!RegulatorType` and `!TargetType` (types of regulator and target: SBO names of physical entity types, e.g. `metabolite`, `enzyme`, `polypeptide chain` (protein), `promoter`, `degradation`, and `transcriptional regulator`, which has no SBO term); `!RegulatoryCoefficient` is NaN for unknown or dual regulation
- Bug fix: `sbtab_table_load` stored the SBtab column names (`column.column_names`) at the positions of the columns in the file, with empty entries for columns without `!` (e.g. the state columns of a QuantityMatrix). When such a table was saved, the header of an SBtab column after these columns was written as `!` (e.g. `!Comment` became `!`)
- Definitions tables: new column `!ActivityCondition` of Regulator tables (SBtab 1.1 and 1.2): compounds that activate or inhibit the regulator, as a regulation formula like in `!KineticRegulation`, e.g. `+ FBP`
- Definitions tables (`resources/definitions`): column `!State` of Regulator tables removed (SBtab 1.1 and 1.2); SBtab 1.2 Regulation tables have the columns `!ID`, `!Target` (was `!Reaction`), `!Regulator` (was `!Compound`), `!RegulationType` (`activation`, `inhibition`, `dual`), `!RegulationType:SBO` and `!RegulatoryCoefficient` (signed Hill coefficient). Example `lac_operon` (SBtab 1.1): column `!State` removed
- New functions `sbtab_table_get_values_by_id` (numerical values of a table column, matched to a list of element IDs, e.g. the reactions of a model; the order of rows does not matter) and `sbtab_table_from_input` (get a table from a file name, a table object, or a document object; used by tools that accept SBtab objects as well as files)
- Definitions tables (`resources/definitions`): new column `!KineticRegulation` of Reaction tables (SBtab 1.1 and 1.2), e.g. `+ ADP - PEP` (`+` activation, `-` inhibition, `+-` dual effect); column `!RegulatorRole` of Compound tables removed; SBtab 1.2: column `!Regulator` of Reaction tables and the relation columns of Regulator tables (`!RegulationType`, `!Cooperativity`, `!Target*`) removed, since Regulator tables describe regulators of gene expression as entities only. Example files: `!Regulator` columns of Reaction tables converted to `!KineticRegulation` (SBtab 1.1 and 1.2 examples)
- Definitions table of SBtab 1.2: new table type `Workflow` (columns `!StepNumber`, `!Tool`, `!InputFile`, `!OutputFile`, `!ConfigFile`) describing the steps of a modeling workflow; the SBtab 1.2 specification explains `Config`, `ToolInputOutput` and `Workflow` tables in the new section "Modeling workflows".
- Definitions table files in `resources/definitions` renamed: `definition_0.9.1_published.tsv`, `definition_1.1.tsv`, `definition_1.2.tsv`, `definition_tool_types.tsv` (was: `definitions_*.tsv`); `sbtab_definitions` reads the new names
- Definitions table of SBtab 1.2: new table type `ToolInputOutput` (columns `!RequiredIn`, `!RequiredTable`, `!TableID`, `!File`, `!IsOptional`, `!RequiredColumns`) describing the input and output tables of a tool (also added to the SBtab 1.2 specification). Documents containing it are written as SBtab 1.2.
- Definitions tables of SBtab 1.1 and 1.2: new columns of `QuantityInfo` tables for priors of multiplicative quantities and related information, as used in parameter balancing and model balancing: `!BiologicalElement`, `!PhysicalType`, `!MathematicalType`, `!PriorGeometricStd`, `!DataGeometricStd`, `!UseAsPriorInformation` (also added to the SBtab 1.1 and 1.2 specifications).
- Extra definitions tables (planned for SBtab 1.2): `sbtab_definitions(version, extra, mode)` extends ('extend', default) or replaces ('replace') the definitions table of a version by extra definitions tables (table objects, files, documents, or cell arrays of these); new functions `sbtab_definitions_merge`, `sbtab_definitions_read`, `sbtab_document_set_definitions` (stores them in the document object, field `definitions`) and `sbtab_document_get_definitions`; `sbtab_document_validate` uses the definitions of the document and has the new option `definitions_mode` (option `definitions` now extends the default definitions by default)
- `sbtab_basedir` now returns the main directory of the repository
- New `GUIDE.md` and `CITATION.cff`; `README.md` has a Quick start section
- `sbtab_document_validate`: the default version for documents without `SBtabVersion` is 1.1; new rules R16 (SBtabVersion of the document repeated in a table declaration row: warning) and R17 (table type of SBtab 1.2 in a 1.0/1.1 document: warning); in SBtab 1.0, `!Identifiers:<resource>` columns are accepted with the published definitions table and `ReactionStoichiometry` gives a warning instead of an error
- `tests/test_examples.m` tests only the SBtab 1.1 examples by default (environment variable `SBTAB_TEST_VERSIONS`, e.g. `1.0,1.1` or `all`)
- Example files with `e_coli` or `ecoli` in their names renamed to `escherichia-coli` (`escherichia_coli` in Matlab function and script names)

## 1.0.0 (2026-10-31)

First numbered version.

- HTML documentation removed from the repository (it can be regenerated with m2html)
- Version function `sbtab_toolbox_version`. This is the version of the code; `sbtab_version` still gives the version of the SBtab file format
- Support for SBtab format 1.1 and validation of SBtab documents
- Tests and README
- Conversion between SBtab and network models, omics data, SBML and COBRA, and `sbtab_model_display`, moved to the Metabolic Network Toolbox (folder `mnt_sbtab_conversion`). SBtab for Matlab now requires only matlab-utils
- `annotate_list` moved here from matlab-utils

The state before the cleanup of October 2026 is available under the git tag `v0.9-legacy`.
